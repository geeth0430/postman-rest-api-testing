# BUG-001 - Invalid Endpoint Returns Unexpected Status Code

## Bug ID
BUG-001

## Title
Invalid endpoint returns 401 Unauthorized instead of expected 404 Not Found

## Module
User API

## API Endpoint
`GET /api/invalidendpoint`

## HTTP Method
GET

## Environment

| Item | Details |
|---|---|
| Testing Tool | Postman |
| Operating System | Windows |
| API | ReqRes |
| Test Type | API Functional Testing |
| Environment | ReqRes Environment |

## Preconditions

1. Postman is installed.
2. The RESTful User API Testing collection is available.
3. A valid ReqRes API key is configured.
4. The request contains the required `x-api-key` header.

## Steps to Reproduce

1. Open Postman.
2. Open the `RESTful User API Testing` collection.
3. Open `TC-006 - Invalid Endpoint`.
4. Select the `GET` method.
5. Enter the endpoint:

   `https://reqres.in/api/invalidendpoint`

6. Add the required authentication header:

   `x-api-key: {{reqres_api_key}}`

7. Click **Send**.
8. Observe the HTTP response status code.

## Expected Result

The API should return:

**404 Not Found**

because the requested API endpoint does not exist.

## Actual Result

The API returns:

**401 Unauthorized**

with an authentication-related response.

## Impact

The unexpected HTTP status code can make it difficult for API consumers and automated tests to correctly determine whether the requested resource or endpoint exists.

## Suggested Investigation

Verify the API authentication flow and endpoint routing behavior.

Confirm from the official API documentation whether an authenticated request to an invalid endpoint is expected to return `404 Not Found`.
